# red-skeleton — 실패하는 테스트 스켈레톤 작성

**모드**: Agent

## 목적

`/red-test-plan` 결과를 바탕으로 **테스트 파일만** 작성한다. 테스트는 **실패하는 상태**여야 RED가 성립한다.

## 절차

1. `/red-test-plan` 표와 README를 확인한다.
2. **테스트 파일만** 작성한다 (`tests/` 또는 프로젝트 관례 경로).
3. **`UnitConverter.py` 및 프로덕션 구현 코드는 수정하지 않는다.**
4. `pytest`로 테스트를 실행한다.
5. 실패 결과를 요약하고 원인을 분류한다.

## 필수 출력

다음 5항을 순서대로 보고한다.

1. **작성한 테스트 파일** — 경로 목록
2. **작성한 테스트 케이스** — 함수명·한 줄 설명
3. **테스트 실행 명령** — 예: `pytest tests/ -v`
4. **실패 결과** — 실패 테스트명·핵심 메시지
5. **실패 원인 분류** — 아래 중 하나 또는 복합

### 실패 원인 분류

| 분류 | 의미 |
| ---- | ---- |
| 기능 미구현 | RED 의도대로 아직 코드가 없음 (정상 RED) |
| 기존 동작 불일치 | Golden Master·현재 CLI와 테스트 기대값 불일치 — 계획 재검토 |
| 테스트 오류 | import 경로, typo, 잘못된 assertion — 테스트 수정 |

## 작성 가이드 (UnitConverter)

- **변환**: `meter:2.5`, `feet:10`, `yard:1` 등 meter 기준 비율 검증
- **형식 오류**: `:` 없음 → `"Invalid format. Use unit:value (ex: meter:2.5)"`
- **숫자 오류**: `"Invalid number: {value_str}"`
- **단위 오류**: `"Unknown unit: {unit}"`
- CLI 테스트 시 `subprocess` 또는 `main()` 호출 방식을 프로젝트에 맞게 선택
- 아직 분리되지 않은 코드라면 **동작(입력→출력/에러)** 기준으로 테스트 작성

## 금지

- 프로덕션 코드 수정으로 테스트 통과시키기
- 테스트 기대값을 현재 버그에 맞춰 약화하기
- P1 범위 테스트를 P0와 한 파일에 대량 추가

## 완료 기준

- 모든 신규 테스트가 **의도적으로 실패**
- 실패 원인이 **기능 미구현**이면 다음 단계 `/green-minimal` 진행 가능

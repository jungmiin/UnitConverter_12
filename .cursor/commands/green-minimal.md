# green-minimal — RED 테스트 통과를 위한 최소 구현

**모드**: Agent

## 목적

실패 중인 RED 테스트를 **통과시키는 최소 구현**만 수행한다. 구조 개선·추가 기능은 REFACTOR 또는 다음 사이클로 미룬다.

## 절차

1. 실패 테스트와 `/red-test-plan` 범위를 확인한다.
2. **테스트 통과에 필요한 최소 코드**만 `UnitConverter.py` 또는 신규 모듈에 추가한다.
3. **테스트 코드를 임의로 수정하지 않는다.** (테스트 오류가 명확할 때만 `/red-skeleton`으로 되돌림)
4. 구현 후 **전체 테스트**를 실행한다.
5. 통과/실패 요약을 보고한다.

## 필수 원칙

- **P1 요구사항은 P0 완료 전 구현하지 않는다.**
- 아직 요구되지 않은 추가 기능을 구현하지 않는다.
- README에 있는 OCP/SRP 분리는 **최소 통과 후** REFACTOR에서 진행한다.

## 금지

- 대규모 리팩토링 (Parser/Registry/Formatter 일괄 분리)
- 출력 포맷 확장 선구현 (JSON / CSV / table)
- 설정 파일 로드 선구현 (JSON/YAML)
- 동적 단위 등록 선구현 (`1 cubit = 0.4572 meter`)
- 테스트 기대값을 구현에 맞춰 **약화**하기
- `if/elif` 나열을 다른 파일로 옮기기만 하고 테스트 없이 구조만 바꾸기

## UnitConverter 최소 구현 힌트

- 현재 `main()`에 있는 로직을 함수로 추출하는 것은 **테스트 통과에 필요할 때만** 허용
- 비율 상수 `3.28084`, `1.09361` 변경 시 Golden Master와 충돌 — 변경 금지
- 에러 메시지 문자열은 기존 `UnitConverter.py`와 **동일**하게 유지 (변경 시 먼저 테스트 고정)

## 완료 후 출력

1. 수정·추가한 파일 목록
2. 통과한 테스트 수 / 전체 테스트 수
3. 여전히 RED인 테스트가 있으면 목록과 다음 액션
4. 다음 권장 명령: `/golden-master` (회귀 고정) 또는 `/test-loop`

## 완료 기준

- `/red-test-plan` 이번 사이클 범위 테스트 **전부 GREEN**
- 범위 밖 테스트는 실패해도 되나, **기존 동작 회귀**가 있으면 중단·원인 보고

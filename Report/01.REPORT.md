## 1. 요약

`UnitConverter.py`를 수정·확장해야 하는 개발자/유지보수자 역할로 Mom Test 인터뷰 25문항을 진행했다. 인터뷰는 해결책 제안 없이 변경 비용, 수정 영향도, 테스트 불안, 책임 혼합, 회귀 위험 중심으로 답했다.

인터뷰 종료 후 페르소나, 표면 문제(잘못된 정의), 진짜 문제(한 문장), Mom Test 증거 3줄을 정리했다. 핵심 진짜 문제는 단위 인식·비율 환산·출력·검증이 `main()` 한 함수에 묶여 있어 수정 시 여러 위치를 동시에 맞춰야 하고, 자동 검증 없이 수동 실행에 의존한다는 점이다.

## 2. 핵심 결정·산출물

| 산출물 | 내용 |
|--------|------|
| 페르소나 | `UnitConverter.py` 코드 변경 책임이 있는 개발자/유지보수자 (최종 사용자 아님) |
| 표면 문제 | README 추가 요구사항을 기능 목록처럼 순차 구현하고 `main()` 분기·출력·비율을 계속 늘리는 방향 |
| 진짜 문제 | 단위/비율 변경 시 다중 위치 수정 + 자동 검증 부재로 수동 확인에 의존하는 상태 |
| Mom Test 증거 | inch 추가 시 3곳 수정, feet 수정 시 출력 불일치 위험, 자동 테스트 없이 수동 실행 필요 |

인터뷰에서 확인된 구체적 마찰:

- 새 단위 추가 시 `elif` 분기, meter 환산, 출력 블록 최소 3곳 수정
- 비율 상수가 입력 분기와 출력 계산에 중복 — 한쪽만 수정 시 불일치
- `input()`·`print()`·변환 로직이 `main()`에 혼재 — 단위 테스트 분리 어려움
- `tests/` 없음 — 리팩토링·수정 후 회귀를 눈으로만 확인

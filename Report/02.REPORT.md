## 1. 요약

Mom Test 인터뷰(세션 01)에서 도출한 페르소나·진짜 문제·증거 3줄을 입력으로, 이번 세션에서 **솔루션을 최소화한 주제 한 문장**, **R-G-I-O**, **Mom Test 증거와 연결된 성공 기준 3개**, **표면 문제(이번 프로젝트에서 하지 않을 것)**를 작성했다.

핵심 주제: 단위·비율 변경 시 다중 수정·비율 불일치·수동 검증 의존을 **구조와 자동 테스트**로 없애는 것. README 추가 요구사항을 `main()` 분기·출력·비율 누적 방식으로 순차 구현하는 것은 이번 프로젝트의 목표가 아님.

## 2. 핵심 결정·산출물

| 산출물 | 내용 |
|--------|------|
| 주제 한 문장 | 단위·비율을 바꿀 때마다 여러 군데를 같이 고치지 않아도 되고, 수정 후 다른 단위 결과가 깨졌는지 자동으로 잡히게 만드는 것 |
| R-G-I-O | Role: 개발자/유지보수자 / Goal: 단일 수정 지점 + 자동 회귀 검증 / Input: `main()` 혼재 구조·README 요구사항·기존 비율 / Output: 수정 지점 명확한 구조·고정 테스트·통과한 리팩토링 결과 |
| 성공 기준 1 | 단위 추가 시 elif·출력·상수 3곳이 아닌 **단위/비율 정의 한 경로**만으로 인식·환산·출력이 맞음 (inch 3곳 수정 증거) |
| 성공 기준 2 | 입력 분기와 출력 계산이 **같은 비율 정의**에서 나와 불일치 시 테스트 실패 (feet elif·in_feet 불일치 증거) |
| 성공 기준 3 | `meter:2.5`·`feet:10`·잘못된 입력 등 **수동 확인 케이스가 테스트로 고정**되어 한 번의 실행으로 회귀 감지 (자동 테스트 부재 증거) |
| 표면 문제 (하지 않을 것) | README 기능을 `main()` elif·print·하드코딩 비율에 순차 누적, 테스트 없이 수동 실행으로만 마무리, OCP/SRP를 이름·주석만으로 충족 |

## 3. 다음 단계

3. **구조 분리**: 단위/비율 정의·환산·출력·검증 경계를 나누어 성공 기준 1·2를 충족하는 리팩토링 착수
